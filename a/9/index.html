微调入门：通识教育之后，再上岗前培训

2026 年 9 月 27 日约 5 分钟炼丹笔记 微调 教程

很多人一上来就说：「我要微调一个自己的模型。」

先别急。微调是最贵、最慢、最难回头的手段，而你可能根本不需要它。

一个比喻：通识教育 vs 岗前培训

把一个开源基座模型想象成一个刚毕业的大学生：

  • 他读过海量书籍，什么都懂一点（通识教育 = 预训练）；
  • 但他不知道你公司的规矩、术语、文件格式（不知道你的业务）；
  • 你要让他上岗，有两条路：
路 怎么做 类比
给他一本手册，让他照着答 RAG / Prompt 给他工具书，边看边干
送他去岗前培训，练成肌肉记忆 微调 反复练，练成本能

微调就是岗前培训：通过喂给它一批「标准答案」并反复训练，把某种行为刻进它的参数里，变成不用你提醒就会做的本能。

先做这道判断题

在动手前，请先确认你要解决的到底是哪种问题：

情况 A：模型不知道某件事 → 用 RAG，别微调

症状：问「我们公司年假几天」，它编了一个通用答案
病因：它没见过你的制度文档 → 缺知识
药方：RAG（第二层第 2 篇）

微调不擅长注入知识。你喂它几份文档微调，它可能记住了这几份，但问到文档外的照样编，而且你没法随时更新——改一次制度就得重新训一次。

情况 B：模型不会按你要的方式说话 → 微调

症状：要求输出严格 JSON，它十次有三次给你加段废话
病因：它不知道你的格式规矩 → 缺行为习惯
药方：微调 ✅

这类问题 RAG 解决不了——你在 Prompt 里贴一百个 JSON 示例，它也可能在长对话后忘了规矩。微调能把「永远输出这种格式」变成它的本能。

情况 C：只是这一次没说清楚 → 改 Prompt

症状：回答太啰嗦
病因：你没提要求
药方：加一句「用三句话以内回答」

别用微调去解决一个 Prompt 能解决的事。

决策表

你的需求 推荐方案 原因
回答私有文档里的内容 RAG 知识随时更新，微调做不到
固定输出格式（JSON / 特定模板） 微调 练成本能，比 Prompt 稳
学会行业黑话、特定术语体系 微调 词汇和用法要刻进参数
模仿特定语气风格（客服话术） 微调 风格是行为习惯
小模型在窄任务上追大模型 微调 专精一个任务可以很强
只是这次答得不好 改 Prompt 最便宜
需要实时/最新信息 RAG 或工具调用 微调的知识会过期

口诀：缺知识 → RAG；缺行为 → 微调；缺交代 → Prompt。

微调到底在做什么

说穿了很简单：

你准备一堆「问题 → 标准答案」的配对数据
            ↓
让模型反复看这些数据，每次都问：
「照你现在的参数，你会怎么答？」
            ↓
把它答的和标准答案对比，算出差距
            ↓
按差距去微调它的参数（让下次更像标准答案）
            ↓
重复成千上万次

这就是监督微调（SFT, Supervised Fine-Tuning）。名字唬人，原理就是「给它看标准答案，让它照着学」。

训练数据长什么样

一般是这样的问答对（JSONL 格式，一行一条）：

{"messages": [
  {"role": "system", "content": "你是客服助手，只输出 JSON，不要任何其他文字。"},
  {"role": "user", "content": "订单 A1024 什么时候发货？"},
  {"role": "assistant", "content": "{\"intent\":\"query_shipping\",\"order_id\":\"A1024\",\"reply\":\"正在为您查询订单 A1024 的发货状态。\"}"}
]}
{"messages": [
  {"role": "system", "content": "你是客服助手，只输出 JSON，不要任何其他文字。"},
  {"role": "user", "content": "我要退款"},
  {"role": "assistant", "content": "{\"intent\":\"request_refund\",\"order_id\":null,\"reply\":\"请您提供需要退款的订单号。\"}"}
]}

注意几个要点：

  • 每条都要带上相同的 system 提示，让它把「身份」和「任务」绑定在一起学；
  • assistant 的回答就是你的「标准答案」，模型会照着这个样子学；
  • 几百到几千条就能见效（取决于任务复杂度），不是越多越好，质量远比数量重要。

数据质量：这一炉的药材

老话重提：数据是药材，药材不纯，丹药必废。

微调会放大数据里的一切问题：

数据里的问题 微调后
标答格式不统一（有的带引号有的不带） 模型输出格式随机
有几条标答是错的 模型学会了那个错误，还很自信
全是简单样本 遇到复杂情况就崩
有偏见/不当内容 直接学会，而且更难消除

⚠️ 一条经验：先花 80% 的时间检查和清洗数据，再开始训练。 在训练到一半发现数据有问题，是最贵的返工。

微调的基本流程

1. 明确目标    「我要它学会什么？怎么算成功？」
                ↓ 先定好评测标准，否则你不知道有没有练成
2. 准备数据     几百～几千条高质量问答对 + 留一部分做测试集
                ↓
3. 选基座       7B 级开源模型起步（Qwen、Llama 系列等）
                ↓
4. 训练         LoRA 起步（下一讲），别一上来就全参
                ↓
5. 评测         用第 1 步定好的标准，在测试集上打分
                ↓
6. 迭代         不行就回去改数据，而不是一味加训练轮数

最常见的错误是跳过第 1 步和第 5 步——训完了不知道有没有变好，只能凭感觉。

炼丹小结

  1. 微调 = 岗前培训，把某种行为刻进参数，变成不需要提醒的本能；
  2. 决策口诀：缺知识 → RAG；缺行为 → 微调；缺交代 → Prompt；
  3. SFT 就是给它看标准答案让它照着学；
  4. 数据质量远重于数量，垃圾数据会被微调放大；
  5. 训练前先定评测标准，训练后必须打分，别凭感觉。
