小米 MiMo：把全模态卖成白菜价的那家

2026 年 9 月 27 日约 26 分钟炉具评测 模型选型 小米MiMo 全模态 开源模型 成本优化

这一系列写到第八篇的时候，我们其实已经默认了一件事：多模态是要加钱的。

要么像 Gemini 那样，Flash 这一档比别人贵一截；要么像早期各家那样，视觉模型单独开一条产品线、单独标一个价；再不济，也得自己在外面挂一套「语音转文字 + 图片理解」的前置管线，把它拼成一个勉强能用的组合。

小米的 MiMo-V2.6 出来之后，这个默认共识被打破了一半：

同一个模型，原样吃进去文字、图片、视频、音频，标价 $0.435 / $0.87——比很多只能读文字的模型还便宜。

这篇文章就讲清楚三件事：它凭什么这么便宜、这个便宜是不是真的、以及哪些活可以放心交给它。

一个比喻：拼装音响与一台整机

先说清楚「原生全模态」（natively omnimodal）这个词到底稀奇在哪。

以前大多数所谓「多模态」模型，其实是拼装音响：

你买一台功放（语言模型），再单独买一个 CD 机（视觉编码器）、一个麦克风（语音转文字模块）、一个解码器，然后自己拿线把它们连起来。能用，但有几个毛病——接插件那里的信号会损耗（模态转换时的信息丢失）、每一件都要单独调试、坏了一个你要自己排查是哪根线松了。

而「原生全模态」是一台整机：出厂的时候，它就是一个同时长着眼睛和耳朵的人。视觉编码器、音频分词器、语言主干一体训练，图像占多少个 token、视频抽多少帧、音频怎么切片，全是模型自己内部的事。

拼装音响（外挂管线） 一台整机（原生全模态）
信息损耗 每次转换都掉一层 原始信号直接进模型
要维护的部件 好几个，还可能来自不同厂商 一个
延迟 串行串联，累加 一次前向
账单 每一件各算各的 只有一张
出错时查谁 你自己查 找一家

对我们的教训很直接：当「多模态」从加价项变成标配，最先受益的不是做图像的人，而是所有需要一次性塞进混合材料的活。

比如客服质检。以前的标准做法是：录音先走 ASR 转文字 → 文字再进大模型分析 → 中间还得在 Excel 里把元数据对起来。每一道工序都是一次信息损耗和一个单独付费的供应商。 如果有一个模型能直接把音频吃进去，中间那两步的钱和时间就全省了。

小米做整机这件事不算意外——他们本来就是做整机的。真正意外的是价格。

先解释三个型号分别是什么角色，别被名字骗了：

  • Flash 是干活的。它不追求最强，追求「单位成本能买到多少能力」。这一整个系列里，它是最值得我们认真评估的一款；
  • Pro 是旗舰。1.02 万亿总参数、每个 token 只激活 420 亿——典型的稀疏 MoE（混合专家）。还记得第 6 篇讲过的命名规则吗？309b-a15b 这种写法里，前面是总参数、后面是激活参数，总参数决定它装得下多少知识，激活参数决定它算得多快。 这个系列里它俩差了 24 倍；
  • UltraSpeed 不是更强的模型，是更快的服务方式。同一个 Pro 的权重，用更贵的推理集群来跑，官方说输出速度最高能到 20 倍，价格恰好是 10 倍。所以这是一道纯算术题：只有当「用户等待」的价值高于多付的 9 倍价钱时，它才划算。 大部分后台批处理任务不需要它；实时对话、代码补全这类「卡一秒就难受」的场景才值得考虑。

另外官方明确说了两件容易漏掉的事：

  1. 缓存写入限时免费。 很多家写缓存也是要钱的，通常比输入价还贵一档；它现在不收。
  2. 有 Batch API，Flash 和 Pro 都支持。不着急的活走批量通道，一般用半价——这是整个系列里我们已经第三次提到它了，因为它确实是所有省钱手段里性价比最高、改动最小的一个。

缓存折扣：这一家给得最狠

如果说标价是「新客价」，那缓存命中价才是你长期要付的「续订价」。多轮对话、Agent、每天重复喂同一份知识库的场景，账单基本由这一项决定。

型号 输入价 缓存命中价 命中后是输入价的
MiMo-V2.6-Pro 0.435 0.0036 0.83%
MiMo-V2.6-Flash 0.14 0.0028 2.0%
DeepSeek V4.1-Flash 0.15 0.003 2.0%
Claude Fable 5.1 10 0.25 2.5%
Claude Opus 5.5 4 0.20 5%

MiMo-V2.6-Pro 的缓存命中价只有输入价的 0.83%——不到百分之一。 这是目前我们看到公开明示的价格里，折扣比例最深的一家。

配合「限时免费写入」，它的实际意思是：

第一轮你把材料喂进去（几乎不加价），从第二轮开始，重复读这份材料近乎免费。

这对什么活最有价值？Agent。 一个跑三十轮的编码 Agent，每一轮都要重新带上系统提示、工具定义和项目上下文。这些 token 绝大部分是重复的——也就是说，它们的单价会从 $0.435 掉到 $0.0036。 第 3 篇我们用 Claude 算过一次同样的账，一个 Agent 任务三十轮下来能从 $25.2 降到 $3.5；这里只是单价不同，结论完全一样：做 Agent，先优化缓存命中率，再考虑换模型。

顺带提醒一句打折省钱的反面：越是依赖缓存，越要把「会变的东西」放到提示词末尾。 把时间戳、随机数、用户 ID 塞在系统提示开头，等于亲手把缓存全部打碎。这是我们在《炸炉实录》里踩过、花了两天才查出来的坑。

假设每月要处理一批会议录像，折算下来 500 万输入 token（视频 + 图像 + 文字混合）、50 万输出 token：

方案 月账单 能直接吃音频吗
Claude Sonnet 5.5 ≈ $15.00 ❌
Gemini 3.8 Flash ≈ $5.63 ✅（促销价）

⚠️ 这个算例只能看量级。 视频怎么折算成 token，各家口径完全不同（抽帧率、分辨率、时长上限都不一样），上面统一按「输入的 token 数相同」来算，实际差额可能比表上更大或更小。真正要选型，请拿你自己的 20 段真实录像跑一遍。

即便把量级的误差算进去，结论的方向还是清楚的：

  • 处理视频 + 音频这类混合材料，MiMo-V2.6-Flash 和 GLM-5.3-Flash 是一个量级，比 Gemini Flash 便宜 5 倍以上，比 Claude Sonnet 5.5 便宜十几倍；
  • 而且别忘了这只是 API 的钱。如果你原本要走「语音转文字 → 文字再分析」的两段式管线，省下来的还有那家 ASR 服务的账单、两次调用之间的排队时间，以及两边拼起来的一整套胶水代码。

这就是前面那个比喻里「拼装音响 vs 一台整机」落地成钱的样子：部件的账好算，接插件的账没人算，但它一直都在。

开源到什么程度：MIT、9B 蒸馏与一张装机单

MiMo-V2.6 这一代最实在的部分是开源条件：

  • MIT 许可，Pro 和 Flash 的权重都放在 Hugging Face（国内也有 ModelScope），允许商用，没有「仅限研究」的限制条款；
  • 官方同步放出了技术报告、RL 训练框架和七千多个 RL 环境；
  • 还有一个 MiMo-V2.6-Distill-Qwen-9B 蒸馏版，单卡就能跑，适合在本地机器上做实验；
  • 社区侧已经有 SGLang / vLLM 的部署配方。

但请务必读完这一段再热血上头：

「能下载」和「能自部署」之间，隔着一张实实在在的装机单。

按 BF16 每个参数 2 字节粗算，1.02T 参数的权重本身就要 2TB 显存起步；即便压到 FP8 也要 1TB 上下。这不是几张卡的事，是一个机柜的事。

这和第 5 篇讲 DeepSeek 时是同一个道理——开源最大的价值通常不是「我自己跑」，而是三件事：

  1. 没有锁定风险。 供应商哪天涨价、断供、改条款，你手上永远有一条退路（哪怕这条退路你自己不一定走）；
  2. 可以微调。 权重在手，你就能做后面第三层「炼丹」要做的所有事：LoRA、继续预训练、蒸馏成小模型；
  3. 有人替你复查。 技术报告和训练细节是公开的，别人能验证它的说法，而不是只能信一份新闻稿。

对绝大多数学习者来说，正确的入口是那个 9B 蒸馏版：一张消费级显卡就能起来，先把流程跑通，再谈要不要上大家伙。

上手：两条协议、一个免费额度

小米开放平台同时兼容 OpenAI 的 Chat Completions 和 Anthropic 的 Messages 两套协议——和第 5 篇讲 DeepSeek 时的情况一样，这意味着你几乎不用改代码：

import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get("MIMO_API_KEY"),
    base_url="https://api.xiaomimimo.com/v1",   # Anthropic 协议换成 /anthropic
)

resp = client.chat.completions.create(
    model="mimo-v2.6-flash",
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},   # 固定内容放最前，缓存才能命中
        {"role": "user", "content": [
            {"type": "text", "text": "这段录音里客户投诉的是什么？"},
            {"type": "input_audio", "input_audio": {"data": b64, "format": "wav"}},
        ]},
    ],
    max_completion_tokens=2048,
)
print(resp.choices[0].message.content)

几个上手时要知道的细节：

  1. 认证头支持 api-key: 和 Authorization: Bearer 两种写法；
  2. 新账号有一小笔免费试用额度，注册就能把上面这段跑通，不用先掏信用卡；
  3. 思考模式下会多返回一个 reasoning_content 字段。官方文档的建议是：多轮工具调用时，把上一轮的 reasoning_content 原样留在 messages 里，效果最好；但同时它也提示——工具调用时如果开了思考，tool_calls 有可能跑到思考内容里去，所以调用工具时更稳的做法是关掉思考。开不开思考是一次实打实的取舍：开着更准，但也更贵、更容易串格式。
  4. 如果你不想注册新平台，它也在 OpenRouter 上，模型名是 xiaomi/mimo-v2.6-pro，可以先用现有额度验证想法；
  5. 官方还有一个「Token Plan」套餐，买固定额度给专属 key（tp- 开头）和专属入口，适合用量稳定、要做预算的团队。注意token 套餐 key 和按量付费 key（sk- 开头）是两套，不能混用。

直播训练：这件事比那个分数重要得多

这一代最值得我们学习者留意的，其实不是 46 分，而是他们把训练过程公开放映了。

据官方技术报告：一次更新处理 1568 个 prompt、每个 prompt 采样 16 条轨迹，也就是每一步约 2.5 万条轨迹、27 亿到 37 亿个训练 token，而且是在混合环境里同时训练——编码、通用智能体、视觉、网络安全，不分家。Pro 和 Flash 各自只做了 30 次 RL 更新、约 75 万条轨迹，不到六天跑完。 官方自报的开销是 Pro 约 262 万美元、Flash 约 85 万美元。

请注意这个组合：六天、三十步、两百多万美元。 这和我们后面第三层「炼丹」要讲的微调完全不是一个物种。微调是拿现成的丹改个药性，而这是从原料重新开始炼——成本、基础设施、 grading 系统的复杂度都不在一个量级上。

我建议大家关注它的理由有两个：

  • 它是一份公开的、完整的大规模 RL 工程样本。 技术报告、训练框架、七千多个环境都放出来了。想在「模型怎么通过自我博弈变强」这件事上学到真东西，这是眼下少见的一手材料；
  • 它暴露了一个正在成形的路线：靠强化学习而不是靠堆参数往上走。 Pro 从 V2.5 的 19 分冲到 71.9，参数并没有翻几倍，变的是训练方式。这条路线对未来两三年的从业者来说，可能比任何一个具体模型的名字都重要。

同时也别忽略它的对外依赖：有报道指出，它的蒸馏阶段用过其他厂商的模型当「老师」之一。这不是污点，是这个阶段的常态——但它提醒我们，所谓「完全自主」在今天的产业链里是个相对词。

全系列收尾：这一趟我们学到了什么

回头看这整整九篇「选炉」笔记，其实只讲了五件事：

  1. 价格差了一百倍，能力没差一百倍。 所以用「能力下限」而不是「能力上限」选型，才是降本的正路。
  2. 标价是给「一次性无重复请求」看的。 你的真实账单由缓存命中率决定；对多轮对话和 Agent 来说，缓存优化通常比换模型有效得多。MiMo 把这一项做到了不到输入价的 1%，这不是巧合，是新一代竞争的主战场。
  3. 各家都有隐蔽的价格台阶：Claude 不加价；GPT 超过 272K 加；Gemini 超过 200K 整单重定价；GLM 从 32K 就开始分档；DeepSeek 按时间分峰谷。做长期预算前，先找出你用量所在的那一级台阶。
  4. 「多模态」「长上下文」这些曾经的加价项，正在一个接一个变成标配。 一年前要为视频单独签一家供应商的钱，现在可能已经含在 $0.14 的输入价里了。这提醒我们：选型结论的有效期大约只有一个季度。
  5. 最终结论只在自己的数据上成立。 拿 100 条真数据做一次回归测试的成本是几个小时；拿厂商榜单做采购决策的成本，往往是一个季度的预算。

炼丹小结

  1. MiMo-V2.6 是「原生全模态」：文字、图片、视频、音频进同一个模型，不用外挂管线——省下的不只是 API 的钱，还有接插件的那些隐性成本。
  2. 价格是它的核心武器：Flash $0.14 / $0.28（≈ $1.96/月 的标准口径），就能吃到全模态，排进全场最便宜的一档；Pro $0.435 / $0.87 却已摸到第一梯队的 Agent 能力。
  3. 缓存给得最狠：Pro 缓存命中 $0.0036，是输入价的 0.83%，且限时免写入费。做 Agent 时，先把提示词顺序调对再加它是第二步。
  4. UltraSpeed 是「用钱换时间」：快 20 倍、贵 10 倍，只有当等待成本高于那 9 倍差价时才值得。
  5. MIT 许可、权重公开、还有 9B 蒸馏版，但你得清楚 1.02T 参数意味着 TB 级显存——开源真正的价值是「不被锁定」和「可以微调」，不是「人人都自己跑」。
  6. 看榜单要分层信：Agent 类（AutomationBench 53.1、Terminal Bench 2.1 89.9）确实进了第一梯队；但 Terminal Bench 4.0（34.9）与 ExploitBench（47.9）明显落后闭源旗舰——同一张卷子难度一变，结论就变。
  7. 它更值得我们关注的是训练路线：30 步 RL、约 6 天、两百多万美元把 DeepSWE 从 19 分推到 71.9。靠训练方法而非堆参数往前走，可能是未来几年最重要的那条路。
  8. 它同时兼容 OpenAI 与 Anthropic 协议，https://api.xiaomimimo.com/v1；新账号有免费额度，另外 OpenRouter 上也能直接试 xiaomi/mimo-v2.6-pro。

丹成不必在我，火候自有记录。

到这里，「主流模型使用」这一层就算是补齐了。回顾全站主线：第一层「识丹」搞清楚大模型是什么，第二层「用药」学会提示词、RAG、上下文与工具调用，而刚刚收尾的这一层，学的是怎么给每一类活挑对师傅。 再往后才是第三层「炼丹」——当市面上所有现成的炉具都满足不了你的时候，才轮到我们自己动手。

有意思的是，小米恰好在最后这篇里给我们留了一个伏笔：他们把训练过程、七千多个环境和框架全部公开了。下一层我们要动手炼丹，而这次居然有人把别人炼丹的全过程录了个直播放在架子上。 这也算是我们这一代炼丹学徒的运气。
