GPT 家族：菜单铺得最全，账单也最会骗人

2026 年 9 月 27 日约 9 分钟炉具评测 模型选型 GPT OpenAI 成本优化

我们第一次把 GPT 家族全部档位摊开在一张纸上时，反应是：这哪是一个模型，这是一张餐厅菜单。

以前买模型像买电脑，一个型号一个价。现在 OpenAI 卖的是「工种套餐」——同一个 GPT-6 底子，切成了旗舰、主力、轻量、加急四档，每一档的收费方式还不一样。

这篇就干一件事：把这张菜单翻译成人话，告诉你哪一档干什么活最划算。

一个比喻：装修队的四个人

GPT 家族的档位 装修队里的角色 什么时候请他
GPT-6 Astra 首席设计师 全公司最难的那一个问题
GPT-6.1 Sol 主力老师傅 日常绝大多数硬活
GPT-6 Luna 手脚麻利的小工 每天重复一万遍的简单活
Ultrafast 档 加急专线 用户在屏幕上盯着等的时候

有了这个分工，选型就不再是「哪个最强」，而是「今天这个活该派给谁」。

四档明示价格（核对时间：2026 年 10 月初）

单位为美元 / 百万 token。

档位 模型名 上下文 输入 输出 一句话定位
旗舰 gpt-6-astra — 10 50 最强，也最贵
主力 gpt-6.1-sol 1,050,000 2 10 绝大多数人的默认答案
轻量 GPT-6 Luna — 0.10 0.50 量大且任务固定
加急 Ultrafast 档 — 见下 见下 换速度为钱

主力档还有两个细节值得单独拎出来说：

  • 缓存后的输入只要 $0.10（相当于输入价的 5%）——这是整张菜单里性价比最高的一项；
  • 超过 272K token 的请求会加价（社区资料显示约是输入 ×2、输出 ×1.5），具体是按整单还是超出部分计，请以官方文档当下的说明为准。

加急档的价格也需要解释一下，它的逻辑是「同一模型按速度加价」：

Ultrafast 版本 输入 输出 速度
Astra Ultrafast ≈ 60 ≈ 300 最高可达约 300 tok/s
6.1 Sol Ultrafast ≈ 12 ≈ 60 同上

也就是说，同一个模型，你愿意多付 6 倍的钱，它就给你 3～5 倍的手速。

上手：一个最小可用调用

OpenAI 现在推荐用 Responses API（而不是老的 Chat Completions），最小骨架长这样：

from openai import OpenAI

client = OpenAI()

SYSTEM = "你是我们公司的订单助手。只根据提供的资料回答，资料里没有就回答『未查询到』。"
# ↑ 这段要保持「一字不改」地反复出现在每次请求最前面，
#   它是缓存命中的最大来源 —— 命中后这部分输入只收 $0.10/M。

resp = client.responses.create(
    model="gpt-6.1-sol",
    input=[
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": question},
    ],
    max_output_tokens=1024,
)
print(resp.output_text)

这段代码里真正值钱的是那行注释。

我们做过一次对比：一套每天调用两万次的问答服务，系统提示词 1200 token 左右。把系统提示词固定下来、并把用户的历史对话按「最近 N 轮」截断重排之后，缓存命中率从近乎为零升到七成，同一套逻辑，月账单少了一半多。

这件事和 temperature 参数无关，和 Agent 无关，纯粹是把「重复的东西放在最前面、且不让它变」——相当于你每天递材料给师傅，头三页永远印一个样，他扫一眼就知道不必重读。

一句话总结：GPT 家族贵在「全能 + 生态」，不在某一项极致。 你要的是「无论什么奇怪的活它大概率都能接住」，OpenAI 到今天仍然是那个最稳的答案。

它的能力边界（认真说一下）

OpenAI 在 2026 年 9 月底的更新里公布过一组自测数字（引用时请注明「据 OpenAI 官方公布」）：

  • 在 Terminal-Bench Science 0.1 上，6.1 Sol 满 effort 时的表现约为 GPT-6 Sol 的两倍以上，单任务成本约 $5.47，而同期对比 Claude Opus 5.5 约 $23.21、Astra 约 $23.80；
  • 在一份「埋 bug」测试中，6.1 Sol 每轮找出 44/105 个 bug，花费约 $6.56；Astra 找出 45 个，花 $33；
  • 幻觉率与事实错误率据称从约 60% / 11.4% 降到 54% / 7.7%。

这些数字说明三件事：

  1. 主力档以极低成本逼近了上一代旗舰的效果——这是 2026 年最实在的一个变化；
  2. 「约四分之一的答案仍可能有瑕疵」，所以涉及钱、法务、医疗的活，必须有人复核；
  3. 厂商自测成绩永远要打折看，在你自己的 100 条数据上大概率会低一些。

另外必须说一句安全上的共同底线：无论用哪家模型的 Agent 能力，都要给它最小权限、跑在沙箱里，删除/改写/转账这类高危操作一律二次确认。 这不是针对某一家，是所有 Agent 工程的通用守则——模型的「理解」和「执行权限」之间，必须隔着一层人工闸门。

什么时候不该用 GPT

  • 你需要把权重拿回自己服务器 → GPT 是闭源商业 API，做不到。换 DeepSeek / Qwen / GLM 的开源版本。
  • 你的活极其单一且量大 → 比如每天 20 万条情感二分类。用 Luna 甚至开源小模型自己跑，成本能再低一到两个数量级。
  • 你的数据不能出境，且没有合规通道 → 走国产阵营（第 6、7 篇）。
  • 你的瓶颈是延迟而不是质量 → 先想想是不是该优化上下文（堵塞住的往往是「每次都重发 50K 材料」），而不是买更快的档。

炼丹小结

  1. GPT 家族不是「一个模型」，是四个人的装修队：Astra 首席、Sol 主力、Luna 小工、Ultrafast 加急。
  2. 绝大多数人默认该用 gpt-6.1-sol（$2/$10，1.05M 上下文），而不是旗舰档。
  3. 缓存后的输入降到 $0.10，把系统提示词固定且放最前面是收益最高的一步优化。
  4. 超过 272K 的请求会加价，规则以官方文档为准；长文档需求务必先把这条算进去。
  5. Ultrafast 是「多花 6 倍钱买 3～5 倍手速」，只在用户盯着屏幕等的时候值。
  6. 厂商自测数字要打折，最终结论请在自己的 100 条数据上测出来。
