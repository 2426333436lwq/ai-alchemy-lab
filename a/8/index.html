LoRA 是什么：不动丹体，只贴一张便利贴

2026 年 9 月 27 日约 5 分钟炼丹笔记 微调 LoRA 教程

上一讲我们说要微调。你兴冲冲地去查教程，然后被显存需求劝退了：

微调一个 7B 模型？请准备 80GB 以上显存。

一张 A100 80G，或者两张 4090。对个人开发者来说，这基本等于「炼丹是卡大户的专利」。

直到 LoRA 出现。

一个比喻：百科全书和便利贴

想象模型是一本已经印好的 1000 页百科全书。

现在你想让它变成「专门讲你们公司业务的百科全书」。两条路：

路 怎么做 代价
全参数微调 把整本书重新印刷一遍，每一页都改 昂贵、耗时，还得保存一整本新书
LoRA 书一个字都不动，在相关页上贴便利贴，写补充和更正 只需几十张便利贴，随时可撕

LoRA（Low-Rank Adaptation，低秩适配） 干的就是「贴便利贴」这件事：

冻住原模型的所有参数（一个字都不改），只在旁边训练一对很小的矩阵，用的时候加在原参数上。

原理：大白话版本

原模型里有很多巨大的数字矩阵（权重）。全参数微调要把这些矩阵里每一个数字都更新一遍——7B 就是 70 亿个数字，这就是显存爆炸的原因。

LoRA 的做法很聪明。它不直接改那个大矩阵，而是：

原来：  输出 = 大矩阵 W × 输入          ← W 有 70 亿个参数，全都要改

LoRA：  输出 = 大矩阵 W × 输入  +  (小矩阵 B × 小矩阵 A) × 输入
              ↑ 冻住不动，不训练           ↑ 只训练这两个小东西

其中的关键在于：如果大矩阵 W 是 4096 × 4096（约 1600 万个参数），LoRA 用 4096 × 8 和 8 × 4096 两个细长条相乘来代替——参数量从 1600 万降到 6.5 万，只有原来的 0.4%。

那个 8 就是著名的超参数 rank（秩），你可以理解成「便利贴的大小」。

数字对比：为什么 LoRA 这么省

全参数微调 LoRA
可训练参数 70 亿（全部） 几百万（通常 0.1%～1%）
显存需求（7B 级） 数十 GB 起 消费级显卡（如 16～24GB）常常够用
训练速度 慢 快很多（要算的参数少了）
产物大小 一整个新模型（十几 GB） 几十 MB 的小文件
换任务 要重新训一个完整模型 换一张「便利贴」就行

最后两项是 LoRA 被疯狂采用的真正原因：产物只有几十 MB，意味着你可以一个基座模型配 N 张便利贴，按任务随时切换，存储和分发成本几乎为零。

上手代码

用 Hugging Face 的 peft 库，改动很小：

from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

# 1. 加载基座模型（可以用量化版省显存）
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-7B-Instruct")

# 2. 贴上「便利贴」
config = LoraConfig(
    r=16,                              # rank：便利贴大小，见下文
    lora_alpha=32,                     # 缩放系数，一般设成 r 的 2 倍
    target_modules=["q_proj", "v_proj"],  # 贴在哪些层上
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, config)

# 3. 看看省了多少
model.print_trainable_parameters()
# trainable params: 8,388,608 || all params: 7,616,000,000 || trainable%: 0.11%

看到那个 0.11% 了吗？这就是 LoRA 的魔法。

训完之后：

model.save_pretrained("my_lora")   # 只存便利贴，通常几十 MB

# 想把它和原模型合并成一个完整模型也可以
merged = model.merge_and_unload()
merged.save_pretrained("my_merged_model")

rank 怎么选

r 是 LoRA 最重要的超参，它决定「便利贴有多大」：

r 值 特点 适合
4 ～ 8 极小，学的东西少 简单格式任务、风格微调
16 ～ 32 常用区间 大多数任务从这里起步
64 ～ 128 容量大 复杂任务、要学较多新知识

选择原则：

  • 任务越简单、数据量越小 → r 越小；
  • r 太大会过拟合（记住训练数据但不会泛化），也会拖慢训练；
  • 从 16 起步，效果不够再往上加。

lora_alpha 一般直接设成 r 的 2 倍，是个省心的默认值。

LoRA 的局限（别神化它）

局限 说明
学大量新知识不如全参 便利贴容量有限，塞不下太多新东西。要注大量知识，还是得 RAG
rank 太小会欠拟合 任务复杂但 r 设成 4，怎么训都训不好
对超参敏感 学习率、rank、target_modules 都会影响结果，要调

经验法则：LoRA 擅长学「行为和格式」，不擅长学「大量事实知识」。 这跟上一讲的结论是一致的——缺知识找 RAG。

炼丹小结

  1. LoRA = 冻住原模型，只训练一对小矩阵，参数量降到 0.1% 量级；
  2. 比喻：不动百科全书，只在页边贴便利贴；
  3. 三大好处：省显存（消费级显卡可跑）、产物小（几十 MB）、可插拔（一基座配多任务）；
  4. rank 从 16 起步，任务简单往下调，复杂往上调；
  5. 局限：擅长学行为格式，不擅长灌大量知识。

有了 LoRA，炼丹的门槛从「卡大户」降到了「一张消费级显卡」。

但到这里为止，我们讲的都是监督微调——给它看标准答案让它照着学。而 2026 年让模型变强的真正主力，是让它自己做题、自己对答案。
