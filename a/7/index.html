后训练的六道火候：大模型是怎么「刷题」变强的

2026 年 9 月 27 日约 8 分钟炼丹笔记 微调 RLVR 后训练 强化学习

前两讲讲的 LoRA、SFT，都是监督微调：给它看标准答案，让它照着学。

但 2026 年真正让模型变强的主力，是另一套东西。它更像——刷题。

两种学习方式：抄答案 vs 刷题

监督微调（SFT） 强化学习（RL / RLVR）
像什么 抄标准答案 自己做题，做完对答案
过程 看「题目 + 标准解答」，模仿 自己做，对了给奖励，错了没奖励
学到什么 格式、语气、套路 解题能力本身
上限 超不过它抄的那份答案 可能超过老师（自己摸索出更优解）

为什么 RL 的上限更高？因为抄答案只能学到「这份答案怎么写」，而刷题能让模型自己发现更好的解法——包括人类没写过的解法。

RLVR：有标准答案的刷题

RL 有个老大难问题：谁来当裁判？

让人类给每条回答打分？太贵、太慢、还带主观偏见（这就是早期的 RLHF）。

RLVR（Reinforcement Learning with Verifiable Rewards，带可验证奖励的强化学习） 的解法极其聪明：

找那些「答案对不对可以自动判定」的任务，让程序当裁判。

任务 自动裁判 奖励
数学题 答案等于标准答案吗？ 对 = 1，错 = 0
写代码 跑单元测试，过了吗？ 全过 = 1，否则 0
工具调用 工具成功返回了吗？ 成功 = 1

不用人，不用训练打分模型，一个 Python 解释器就能当裁判。干净、便宜、可无限扩展。

这就是 2026 年各家「推理模型」变强的核心引擎。

刷题流程长什么样

① 出一道题：「求 1287 × 431」
② 让模型自己写解题过程，采样 16 份不同的答案
③ 自动判分：对了的给 1 分，错的给 0 分
④ 调整参数：让「能得出正确答案的写法」概率变高
⑤ 回到 ①，刷下一批题

看起来简单，但实操中全是坑。2026 年上半年，圈内公认的六个精细化方向，就是踩这些坑踩出来的经验。

我按「你会遇到它们的顺序」来讲。

火候一：选题——别给太简单或太难的题

症状：烧了几万次采样，模型没什么长进。

原因：你的题库里，大部分题太简单（模型本来就会，做对了也没学到东西），还有一部分太难（怎么都做不对，学不会）。

白话：让高中生刷小学加减法，刷一万道也不会变强。

解法：专挑中等难度的题——模型有时做对有时做错的那种，这才是有学习信号的区间。有研究用一个小模型来预测题目难度，据此筛题，最多能省掉 69% 的采样开销。

火候二：探索不足——16 份答案长得一模一样

症状：采样 16 份解题过程，结果几乎一模一样，错了全错在同一个地方。

原因：模型「不敢」尝试新路径，只敢走它最熟悉的那条。

白话：一个学生做题只会用老师教的那一种解法，从不想别的可能。那他永远不会发现更优解。

解法：找到解题过程中那些模型真正「犹豫」的岔路口，在那里强制它分叉探索，再筛掉无效分支。有工作的报告是准确率 +5.3%、多样性 +7.4%。

火候三：熵坍塌——输出越来越同质

症状：刷了一阵之后，模型的输出越来越像同一个模子刻出来的。在需要创意的场景尤其明显。

原因：训练过程中策略分布的「熵」持续下降，概率都压到了少数几条「最安全」的路径上。

白话：学生刷题刷成了「标准答案复读机」，只会一种套路，丧失了灵活性。

解法：别粗暴地整体调高随机性（那会引入胡说），而是只对那些「熵骤降」的位置做精细干预。有工作在数学模型上把平均分从 44.2 提到 48.6。

火候四：能力边界坍缩——最反直觉的一个

症状：pass@1（第一次就做对的概率）一路涨，看着很美。但 pass@256（做 256 次至少对一次的概率）反而跌破了训练前的基座模型。

原因：模型只是把本来就会做的题做得更确定了，而把难题的能力弄丢了。

白话：学生把简单题练到满分，但把难题彻底放弃了。平均分涨了，真实能力降了。

这一条是全文最该记住的：

# 别只盯 pass@1，它会骗人
metrics = {
    "pass@1":   estimate_pass_at_k(samples, k=1),
    "pass@256": estimate_pass_at_k(samples, k=256),  # 真实能力边界
}
# pass@1 涨 + pass@256 跌 = 变窄了，不是变强了

判据：pass@1 涨而 pass@256 跌，就是「炸炉前兆」。这时候加算力只会加速坍缩，正确的做法是换题库、专攻边界上的题。

火候五：灾难性遗忘——推理强了，别的垮了

症状：数学能力上去了，但它写文案变僵硬、翻译变差、闲聊变得像在做题。

原因：训练数据全是数学题，模型的参数全往「做数学题」的方向偏。

白话：学生为了备考数学，把语文英语全丢了。

解法：训练时掺入通用数据回放，并按「目标收敛程度」和「不稳定程度」动态调整权重——已经学得好的少练，正在退步的多练。

火候六：参数效率——能不能只练 0.5%

症状：RL 训练太贵，显存吃紧。

一个有意思的发现：研究者观察到 RLVR 的更新极其稀疏，而且会系统性地避开预训练形成的主方向——也就是说，它只需要改动很小一块子空间。

解法：用几何先验定位这块子空间，压缩成低秩适配器（跟 LoRA 的思路相通）。有工作报告 0.5% 的参数就能逼近全参数训练的效果。

附带一条打脸经验：SFT 不是「无害的热身」

过去大家都觉得：SFT 只是教它听指令，随便训训，checkpoint 越强越好，反正后面 RL 会接管。

这个认知被推翻了：研究发现，一个更强的 SFT checkpoint，在接完全相同的 RL 流程之后，最终效果可能更差。

原因是分布错配：SFT 学的是离线数据分布，RL 是在线自己采样。两者差太远，RL 起步就「懵」。

实用建议：选 SFT checkpoint 时，别只看评测分数，要看它采样出来的东西和你的 RL 任务像不像。

火候小结：开炉前过一遍

  • 选题：是不是在给太简单/太难的题白烧算力？
  • 探索：采样 16 份是不是长得一模一样？
  • 多样性：输出是不是越来越同质？（熵坍塌）
  • 边界：pass@1 和 pass@256 一起看，别被单一指标骗了
  • 别忘本：通用能力有没有掉？
  • 参数预算：必须全参吗？0.5% 能不能打平？
  • SFT 检查点：它的分布和 RL 任务一致吗？
  • 数据：药材你自己信得过吗？垃圾进，RL 只会让你更高效地学会垃圾

写在最后

回头看这六道火候，你会发现它们讲的是同一件事：

刷题的目的不是「把会做的题做到满分」，而是「把不会做的题学会」。

所有会让模型「变窄」的操作——只刷简单题、只敢走老路、把概率压到几条安全路径上——短期看指标都在涨，长期看能力在坍缩。

炼丹这行最贵的教训，往往不是「没烧够」，而是**「烧错了方向还加了三倍火」**。
