RAG 入门：把闭卷考试改成开卷考试

2026 年 9 月 27 日约 5 分钟药方研究 RAG Agent 教程

假设你想做一个「公司制度问答助手」。你兴冲冲地问模型：

我们公司年假有几天？

它很流畅地回答：「一般入职满一年享 5 天年假……」

问题是：它根本不知道你们公司的制度。 它在接一段「公司年假通常怎么规定」的最像的话。这就是幻觉（第一层第 4 篇）。

RAG 就是来解决这件事的。

一个比喻：闭卷考试 → 开卷考试

直接问模型 用 RAG
像什么 闭卷考试：只能凭记忆答 开卷考试：可以翻资料
不知道时 硬编一个像样的答案 翻资料找，找不到就说「没找到」
知识更新 要重新训练 改文档就行，立刻生效
能答私有内容吗 不能 能

RAG（Retrieval-Augmented Generation，检索增强生成），说人话就是：

先从你的资料里找出相关段落，把这些段落和问题一起交给模型，让它照着资料回答。

三步走，就这样

第一步 · 切块   把你的文档切成一小段一小段
                 （比如制度手册切成 300 字一段）

第二步 · 检索   用户提问时，找出和问题最相关的几段
                 （用向量相似度，后面解释）

第三步 · 生成   把「问题 + 找到的段落」一起塞给模型
                 加一句：只能根据资料回答，没有就说没有

第二步怎么「找出最相关的」？

最常见的做法是向量检索，一句话说清：

  1. 用一个 embedding 模型，把每段文字变成一个数字数组（向量）；
  2. 把用户的问题也变成向量；
  3. 算谁的向量和问题向量最接近（余弦相似度），最接近的那几段就是最相关的。

好处是它比「关键词匹配」聪明——你问「休假怎么算」，它能找到写着「年假、事假、病假」的段落，即使没有「休假」这两个字。

完整例子：从编造到准确

改造前（闭卷）：

你是一个助手，请回答：我们公司年假有几天？

→ 模型：「一般入职满一年享 5 天年假……」（编的，可能和你公司差十万八千里）

改造后（开卷）：

你是一个助手。请只根据以下【资料】回答问题。
如果资料中没有提到，请直接回答「资料中没有提到」，不要自行补充。

【资料】
《员工休假管理制度》第三条：员工入职满 6 个月后可享受年假，
年假天数按司龄计算：满 6 个月不满 1 年为 3 天；满 1 年不满 3 年为 5 天；
满 3 年及以上为 10 天。年假需提前 3 个工作日提交申请。

【问题】
我们公司年假有几天？

→ 模型：「根据《员工休假管理制度》第三条，年假天数按司龄计算：
   满 6 个月不满 1 年为 3 天；满 1 年不满 3 年为 5 天；满 3 年及以上为 10 天。」

差别的关键有两处：

  1. 给了资料——它有东西可依，不用猜；
  2. 给了退路——「没有就说没有」，让它不必硬撑。

第二句千万别省。 只给资料不加这句，它照样会编。

最小可用代码

不用装向量数据库，二十行就能跑起来感受一下（示意代码，需装 openai 和你选的 embedding 服务）：

# 1. 切块
chunks = split_text(open("hr_policy.txt").read(), size=300)

# 2. 建索引（把每段变成向量）
index = [(embed(c), c) for c in chunks]

# 3. 检索：找最相关的 3 段
def retrieve(question, k=3):
    q = embed(question)
    scored = sorted(index, key=lambda x: cosine(q, x[0]), reverse=True)
    return [text for _, text in scored[:k]]

# 4. 生成：把资料和问题拼在一起
def ask(question):
    context = "\n\n".join(retrieve(question))
    prompt = f"""请只根据以下【资料】回答问题。
如果资料中没有提到，请直接回答「资料中没有提到」，不要自行补充。

【资料】
{context}

【问题】
{question}"""
    return llm(prompt, temperature=0)   # 注意温度调低

真实项目里你会用现成的库（LangChain、LlamaIndex）或向量数据库（FAISS、pgvector、Milvus）。但原理就是这四步，先用最土的方式跑通，再换工具。

四个新手常踩的坑

坑 症状 怎么调
切块太大 找回来一大段，塞满上下文，模型被无关内容干扰 切小一点（200～500 字），段与段之间留一点重叠
切块太小 语义被切断，一句话断成两半，检索不准 按段落/小节切，别按字数硬砍
检索不准 找到的段落和问题无关 换更好的 embedding 模型；试试「关键词 + 向量」混合检索
没加退路句 资料里没有它也照编不误 务必加「没有就说没有」

什么时候 RAG 不够用？

RAG 解决的是「模型不知道」的问题。但如果你遇到的是下面这些，RAG 帮不上忙，得考虑微调（第三层）：

  • 你要求它永远输出某种固定格式（比如严格 JSON）——这是「行为习惯」，不是知识；
  • 你要它学会你们行业的黑话和术语体系；
  • 你要它模仿某种特定的语气风格；
  • 你要一个小模型在某个窄任务上逼近大模型——靠「翻资料」不够，得靠练。

判断口诀：缺知识 → RAG；缺行为/格式/风格 → 微调。

炼丹小结

  1. RAG = 开卷考试：先检索你的资料，再把资料和问题一起给模型；
  2. 四步：切块 → 向量化 → 检索 → 拼进 Prompt 生成；
  3. 「资料里没有就直接说没有」这句话必须加，否则它照编；
  4. 生成时把 temperature 调低（0～0.2），这时候要的是准确不是创意；
  5. 缺知识用 RAG，缺格式/风格用微调——别搞混。

RAG 是整个系列里性价比最高的一招：不用训练、改文档立刻生效、对幻觉立竿见影。
