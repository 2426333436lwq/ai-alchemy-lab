炼丹房后台收到最多的私信，永远是这一句：

> 「老师，现在最强的模型是哪个？」

说实话，这个问题我们答不上来——**因为问错了。**

打个比方。你要装修房子，问「哪个师傅手艺最好」，然后请一个国宴大厨来通下水道。他手艺确实好，通完你的账单会很难看，而且他大概率还是会叫你另请一位。

**模型选型不是选「最强」，是给每个工种请对师傅。**

这一篇是整个「主流模型使用」系列的总纲。后面八篇会把 GPT、Claude、Gemini、DeepSeek、通义千问、GLM、其他玩家以及小米 MiMo 一家一家拆开讲。**先看这一篇建立坐标系，再看单篇才不会晕。**

## 先把三个问题问对

下次有人问你「用哪个模型」，先反问他三个问题：

| 要问的 | 翻译成人话 | 决定了 |
| --- | --- | --- |
| **这个活的能力下限在哪** | 这项任务最少得多聪明才不会出事 | 排除一半的选项 |
| **这个活一天要干多少遍** | 量 × 单价 = 真金白银 | 贵的模型能不能用得起 |
| **干错了代价多大** | 是推荐错一首歌，还是删错一张表 | 要不要加钱买保险 |

只有把这三问答完，「最强」这个词才落地。

## 八个规格名词，翻成厨房话

各家官网的参数表长得吓人，其实翻成人话就这八件事：

| 术语 | 厨房里的说法 | 你真正该在意的 |
| --- | --- | --- |
| **上下文窗口** | 师傅一次能摊开看多少材料 | 你的材料塞得下吗 |
| **最大输出** | 他一口气能写多长 | 长文会不会被腰斩 |
| **输入价格** | 你递进去的材料，按字数收费 | 材料贵不贵 |
| **输出价格** | 他写出来的东西，按字数收费 | **通常比输入贵 3～10 倍** |
| **缓存命中价** | 同一份材料第二次递，打个大折 | 多轮对话最大的省钱点 |
| **思考 token** | 他先打草稿，草稿也收费 | 各家都按输出价算，常被人忘算 |
| **吞吐量 tok/s** | 手速 | 用户愿不愿意等 |
| **知识截止时间** | 他上次看报纸是哪天 | 问新事就得配联网 |

其中最容易被忽略的是**「思考 token」**。现在的推理模型答问题前会先自言自语一大段，官网会把这段明确写成「含思考 token 的输出价格」。你在 A 模型上测出单次回答 800 字很便宜，换到 B 模型底下偷偷跑了 6000 个思考 token，账单直接翻几倍——**这是新手最常见的「我没改代码怎么超支了」。**

所以真正的省法不是「全换成便宜的」，而是——

## 我们的默认打法：级联路由

**让便宜模型先干，干不好再请贵的。**

像装修公司接活：小工先上门看一眼，能拧螺丝就拧了；发现是承重墙的问题，再摇老师傅过来。

```python
# 级联路由的最小骨架：便宜档先上，顶不住再升级
CHEAP  = "deepseek-flash"   # 闲时 $0.15 / $0.60，日常杂活
STRONG = "claude-sonnet-5-5" # $2 / $10，硬骨头

def route(task: str) -> str:
    """先看这活的「工种」：简单且量大，就走便宜档"""
    if kind_of(task) in {"分类", "抽取", "摘要", "格式转换", "翻译"}:
        return CHEAP
    if len(count_tokens(task)) > 200_000:   # 超长材料，交给不加价的那家
        return STRONG
    return STRONG

def answer(task: str) -> str:
    model = route(task)
    out = chat(model, task)
    # 兜底：便宜档自己说没把握，就加钱请老师傅复核一遍
    if model == CHEAP and not self_check(task, out):
        out = chat(STRONG, review_prompt(task, out))
    return out
```

这个骨架里藏着三个关键判断，比代码本身重要：

1. **`kind_of()` 怎么定？** 只有你自己的业务能回答。先用两个模型各跑 100 条真数据，标出便宜档出错的那几条，看看它们属于哪一类——那几类就是永远不能走便宜档的。
2. **`self_check()` 用什么？** 最糙也最好用的办法：让便宜模型自己给答案打个 0–10 的把握分，低于阈值就升级。别嫌土，**它的成本和「全部走贵档」比起来可以忽略不计**。
3. **路由本身也是成本。** 一个 30 token 的问题被升级到 50 美元档只会更贵，所以阈值要卡在「**返工代价比复核贵**」的那条线上。

这条路走熟了，你再回头看上面那张账单表，会发现一个月能从 $200 砍到 $15 左右，**而效果几乎不掉**——这才是「划算」的正解。

## 三个选型陷阱（我们全踩过）

**陷阱一：只看排行榜。** 排行榜是别人出的卷子。你的活可能根本不在那张卷子上。正确姿势是**拿你自己的 100 条真数据跑一遍**，这一步两个下午就能搞定，比读十篇评测有用。

**陷阱二：忘了算思考 token。** 官网写着「输出价格（含思考 token）」的，那个数字就是最后要乘的全部。越难的活思考越多，账单越难看。这也是为什么 Opus 5.5 那种「想太多」的毛病会直接变成钱。

**陷阱三：把「换模型」当成「换 API 地址」。** 换模型 = 换了一个人。Prompt 要重测、格式约束要重测、语气要重测、甚至分词器都不一样导致同样的中文 token 数不同。我们踩过最狠的一次，是把一套调好的系统提示词从 A 迁到 B，输出格式崩了一半，愣是查了两天才发现是**代码块里那个不显眼的转义符**。

## 炼丹小结

1. 「哪个模型最强」是错问题，正确问法是**能力下限 × 调用量 × 出错代价**这三件事。
2. 八个规格里最容易漏算的是**思考 token**和**长上下文加价阶梯**，这两项最常造成「账突然超了」。
3. 同一个活的账单，在 2026 年 10 月的行情下**最贵与最便宜差约 100 倍**。
4. 省钱的正确姿势是**级联路由**：便宜档先干，自己没把握就升级到贵档复核。
5. 最终结论只在**你自己的数据**上成立，别拿别人的排行榜当采购清单。
6. 所有价格都有时效性——本文数字核对于 2026 年 10 月初，动手前务必复核。
