前面六篇讲的都是「综合医院」型选手：**什么都治，什么都还行。**

这一篇讲三家「专科医院」：**月之暗面的 Kimi、MiniMax、xAI 的 Grok。**

它们的共同点很明确——**不打全面战争，专挑一个项目练到极致。** 对整个市场来说它们是老四老五，但对某一类具体的活来说，它们可能就是全场最优解。

## 一个比喻：综合医院与专科医院

| | 综合医院（GPT / Claude / Gemini） | 专科医院（Kimi / MiniMax / Grok） |
| --- | --- | --- |
| 什么都看吗 | 看 | 主要看一科 |
| 罕见病能处理吗 | 有办法 | 大概率看不了 |
| 专攻的那个病怎么样 | 良好 | **可能是全国最好的** |
| 挂号难吗 | 难、贵 | 相对好挂 |

所以正确用法不是「选一个替换掉综合医院」，而是——

> **在路由表里给每一家专科医院留一个专用入口。**

第 1 篇讲过级联路由的骨架，这篇的终点就是把那张表补全：**哪些活该专门转发给谁。**

## 三家明示价格（核对时间：2026 年 10 月初）

单位美元 / 百万 token，整理自各厂商官方定价文档。

| 厂商 | 型号 | 上下文 | 输出上限 | 输入 | 输出 | 开源 |
| --- | --- | --- | --- | --- | --- | --- |
| Moonshot | Kimi K2.5 | 262.1K | 262.1K | 0.59 | 3.09 | ✅ |
| Moonshot | Kimi K2.6 | 256K | — | （国内约 ¥6.5 / ¥27） | — | ✅ |
| MiniMax | MiniMax M2.5 | 1M | **1M** | 0.30 | 1.20 | ✅ MIT |
| xAI | Grok-4.1 | 256K | **8K** | 3.00 | 15.00 | ❌ |
| xAI | Grok-4.1 Fast Reasoning | **2M** | 30K | 0.20 | 0.50 | ❌ |

看这张表第一眼最该注意到的是**输出上限那一列**：

> **MiniMax M2.5 能一口气输出 1M token，而 Grok-4.1 只有 8K。相差 125 倍。**

这是规格表里最容易被忽略、但最能决定「这活能不能干」的一列。你要一次性生成一本小说、一份完整的技术白皮书、一个大型代码模块——8K 输出意味着你要自己写分段拼接逻辑，而 1M 意味着你可以一次问完。

## Kimi K2.5：数学怪才

Kimi K2.5 发布至今，最醒目的是数学和竞技编程的成绩（数据整理自公开评测聚合站点，**引用请注明来源并自行复现**）：

| 评测项 | Kimi K2.5 |
| --- | --- |
| AIME 2025 | 96.1% |
| GPQA | 87.6% |
| HLE | 50.2% |
| SWE-bench Verified | 76.8% |
| SWE-bench Multilingual | 73% |
| LiveCodeBench v6 | 85% |
| Terminal-Bench 2.0 | 50.8% |
| OSWorld | 63.3% |
| BrowseComp | 74.9% |

注意 **AIME 2025 96.1%** 这个数字——这可是高中数学竞赛题。再配上 GPQA 87.6%、HLE 50.2%，把它归到「推理类模型的第一梯队」是很合理的。

而且它是开源的。所以我们的建议是：

> **如果你的产品里有「硬数学/硬逻辑/竞赛级编程」这类任务，把这部分流量单独挑出来发给 Kimi，其他任务照常发给别家。** 这部分流量通常占比不大，但往往是「成败所在」——正好适合交给专科医生。

另外 Kimi K2.6 也已经上了国内 MaaS 平台（阿里云百炼的吞吐预留清单里就有），宣称在 SWE-Bench Pro 上领先，并支持视频输入。国内站点大约 ¥6.5 / ¥27 每百万 token（仍请以平台实际报价为准）。

## MiniMax M2.5：极端性价比 + 1M 输出

MiniMax M2.5 有两个数字很离谱：

1. **$0.30 / $1.20** —— 输入比 Kimi K2.5 便宜一半，输出便宜六成多；
2. **输出上限 1M** —— 全场最慷慨，没有之一；
3. 它还**开源，MIT 许可**，总参数约 2300 亿 / 激活约 100 亿（MoE），官方给出约 100 tok/s 的吞吐。

它的 SWE-bench Verified 是 **80.2%**，比 Kimi K2.5（76.8%）和 GLM-5（77.8%）都更高一点。也就是说：

> **MiniMax M2.5 是「既便宜，写代码又不见得差」的那种选手。**

这有点尴尬——因为它直接说明了一件事：**给 coding 任务死命上一个昂贵的模型，未必是必要的。**

我们的建议很直接：**如果你手上有一大批 coding/改写类任务在用 $10–20/M 输出的模型，先把它们全量换到 MiniMax M2.5 或同等档位跑一遍自己的回归测试。** 这一步通常两个下午就能完成，而省下的钱往往是按倍数计的。

## Grok：2M 上下文只卖两毛钱

Grok-4.1 本体的价格（$3/$15，256K 上下文、8K 输出）在这一系列里属于偏贵的一档。

但它还有一个版本很有意思：**Grok-4.1 Fast Reasoning——2M 上下文，$0.20 / $0.50，约 90 tok/s。**

请停下来再看一遍：**2M 上下文，输入两毛钱。**

这是整个系列里**单位价格最低的大上下文方案**。对比一下：

| 方案 | 上下文 | 输入 $/M |
| --- | --- | --- |
| Grok-4.1 Fast Reasoning | **2M** | **0.20** |
| DeepSeek V4.1-Flash（闲时） | 1M | 0.15 |
| MiMo-V2.6-Flash | 1M | **0.14** |
| Gemini 3.1 Flash-Lite | 1M | 0.25 |
| MiniMax M2.5 | 1M | 0.30 |
| GPT-6 Luna | — | 0.10 |

但别急着全量切过去，它适合的是这几类活：

- **需要一次性塞进 1M 以上材料的任务**（超长代码库全览、超大文档合订本），它是成本最低的选择之一；
- 它的本体输出上限只有 30K，不适合当写作型模型；
- 它是闭源的，且有成为单一供应商依赖的风险。

另外要提醒一句：**同一个 Grok-4.1 家族，本体的 $3/$15 与 Fast Reasoning 的 $0.20/$0.50 相差了 15 倍。** 选型时别把两版的价格搞混——我们在《炸炉实录》那篇里踩过类似的坑，两个差不多的名字，最后是整整一个数量级的账单差。

## 把它们接进路由表

第 1 篇给过一个最小的路由骨架，这里把它补完整：

```python
# 路由表：每一类活有一个「对口」模型
ROUTES = {
    # ▼ 综合型主力：默认走这里
    "default":        "gpt-6.1-sol",

    # ▼ 便宜且量大：分类 / 抽取 / 摘要 / 翻译
    "bulk_simple":    "deepseek-flash",      # 闲时 $0.15/$0.60
    "bulk_cheapest":  "qwen3.8-flash",       # ≈ $0.11/$0.39

    # ▼ 专科：硬数学 / 竞赛级编程
    "hard_math":      "kimi-k2.5",           # AIME 2025 ≈ 96%

    # ▼ 专科：大批量 coding / 改写
    "bulk_coding":    "minimax-m2.5",        # $0.30/$1.20 + 1M 输出上限

    # ▼ 专科：超过 1M 的超长材料
    "ultra_long":     "grok-4.1-fast",       # 2M 上下文 @ $0.20

    # ▼ 长文档 + Agent：Claude 不给长上下文加价
    "long_agent":     "claude-opus-5-5",     # 缓存读 $0.20

    # ▼ 多模态 + 联网接地
    "multimodal":     "gemini-3.8-flash",    # $0.75/$3.75（2027 起翻倍）
    # ▼ 要能吃视频文件的便宜方案
    "video_cheap":    "glm-5.3-flash",       # $0.15/$0.50

    # ▼ 全模态（图 / 视频 / 音频）里的白菜价，见第 9 篇
    "omni_cheap":     "mimo-v2.6-flash",     # $0.14/$0.28，MIT 开源
    # ▼ 编码 Agent / 工具调用，想用开源替代旗舰档
    "bulk_agent":     "mimo-v2.6-pro",       # $0.435/$0.87，缓存命中 0.0036
    # ▼ 卡延迟的实时场景（先算清楚「等待」值不值那 9 倍差价）
    "realtime":       "mimo-v2.6-pro-ultraspeed",
}

def answer(task: str) -> str:
    model = ROUTES[kind_of(task)]
    out = chat(model, task)
    if model != ROUTES["default"] and not self_check(task, out):
        out = chat(ROUTES["default"], review_prompt(task, out))   # 没把握就升级复核
    return out
```

这张表的核心思想只有一句：**没有哪个模型适合所有活，所以「选一个模型」这个动作本身就是错的；正确的动作是「画一张任务金字塔，给每一层配一个型号」。**

再强调一次第 1 篇那条：这张表只有两个函数 `kind_of()` 和 `self_check()` 需要你自己实现，**而这两件事的答案只能从你自己的数据里来。**

## 什么时候别用这些偏科生

- **你刚起步、还没有自己的回归测试集** → 先用一家综合型模型把产品跑起来，别一上来就搞多模型路由，运维复杂度会反噬你。
- **你的流量很小** → 单价差异在绝对金额上不值得，用得顺手最重要。
- **你对供应商锁定极度敏感** → 优先选开源（Kimi / MiniMax / GLM / Qwen / DeepSeek 都开源），闭源的 Grok 需要额外评估。

## 收个尾：偏科生之外，还有一位全能选手

把这三家接进路由表之后，你手上已经有了一支分工明确的队伍：日常杂活走便宜档、数学难题找 Kimi、大批量 coding 找 MiniMax、超长材料找 Grok Fast、长文档 Agent 找 Claude。

但这套体系里还缺一类：**材料本身是混合的**——一段录像、一堆截图、几份录音，配上文字。这时候第 4 篇讲过的 Gemini 和第 9 篇要讲的小米 MiMo 才登场。它们不打某一科的冲锋，卖的是「什么都吃」这件事本身。

尤其要留意 MiMo：**它是我们这一趟遇到的第一个「多模态不再加价」的信号。** 更多内容请看下篇，我们把它单独拆开讲。

## 炼丹小结

1. Kimi / MiniMax / Grok 是**专科医院**，正确用法是在路由表里给它们留专用入口，而不是全面替换主力。
2. **Kimi K2.5**：数学与竞技编程的怪才（AIME 2025 约 96%），开源，适合只把这部分流量单独转发过去。
3. **MiniMax M2.5**：$0.30/$1.20、**输出上限 1M**（全场最慷慨）、MIT 开源、SWE-bench Verified 约 80.2%——**coding 类流量的第一优先尝鲜对象**。
4. **Grok-4.1 Fast Reasoning**：2M 上下文只要 $0.20/$0.50，是最大上下文的最低成本方案；但注意本体（$3/$15）与 Fast 版**价格相差 15 倍**。
5. **输出上限是最被忽略的一列**：从 Grok-4.1 的 8K 到 MiniMax M2.5 的 1M，差了 125 倍，直接决定你需不需要写分段拼接。
6. 路由只有两个函数需要自己实现：**`kind_of()`（这是哪类活）和 `self_check()`（它干好了吗）**。这两件事的答案只能从你自己的数据里来。
