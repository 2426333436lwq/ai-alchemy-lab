## 写作约定（这个系列统一遵守的）

1. **通俗优先**：每个抽象概念必须配一个生活比喻（猜字游戏、办公桌、拼车、便利贴、开卷考试……），再配一个可运行的例子；
2. **难度递进**：L1 不写代码，L2 开始有小段代码，L3/L4 才上完整工程内容；
3. **篇末小结**：每篇结尾固定是「炼丹小结」编号清单 + 「丹成不必在我，火候自有记录」；
4. **前后呼应**：每篇结尾都会指向下一篇，形成学习链；
5. **事实可查**：涉及具体数字时，文末注明来源并提示读者自行复现验证，不编造。

## 内容来源说明

全部内容基于 2026 年公开可得资料二次创作，未照搬任何单篇文章：

- **原理层**：大模型自回归生成机制、tokenization、幻觉成因；
- **应用层**：采样参数、RAG、上下文窗口与 Lost in the Middle / 长上下文性能衰减（Chroma Research 等公开测试）、工具调用与 Agent 循环；
- **进阶层**：write/select/compress/isolate 四策略、注意力预算、prompt caching 机制；
- **训练层**：SFT / LoRA / RLVR，以及 2026 年后训练精细化方向（熵坍塌、探索不足、难度筛选、能力边界坍缩、防遗忘、低秩参数效率）；
- **选型层（第 2.5 层）**：各家**官方定价页与 API 文档**（OpenAI、Anthropic、Google AI for Developers、api-docs.deepseek.com、阿里云百炼、智谱开放平台 / docs.z.ai、Moonshot、MiniMax、xAI、小米 MiMo 开放平台 / platform.xiaomimimo.com），测试数据补充自公开评测聚合站点与厂商公布的技术报告附录；
- **工程层**：vLLM / SGLang 官方文档与社区实践、量化特性、KV cache 瓶颈与 preemption、投机解码接受率、级联路由；
- **本地部署线**：各项目官方 release 记录（版本号与发布日期）、llama.cpp 官方仓库的量化 bpw 与 `llama-quantize` 自报困惑度增量、社区独立测量 Artefact2 的 KLD 数据、Ollama 官方文档的默认上下文档位与 `keep_alive` 行为、公开量化格式资料（AWQ / GPTQ / FP8 / MXFP4 / NVFP4）、国产 NPU 的公开部署文档。

### 选型层的三条额外约定

1. **必须写「核对时间」**：每篇开篇的价格表都要标注核对日期，并提示读者下单前复核；
2. **必须做横向对比**：每家厂商的单篇里，都要有一张与至少 3 家同类的对照表（这是本系列的核心要求——「互相对比着写」）；
3. **不许只谈性能**：每篇都必须回答「哪个模型干什么活最划算」，给出具体单价或算例。
