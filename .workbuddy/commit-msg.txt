fix(search): 修复搜索的三个真实缺陷（分页消失 / 逗号崩溃 / 多词零结果）

1. 搜索结果的分页器整个消失（最隐蔽）
用 .or() 之后云库返回的 count 恒为 null（实测）。listArticles 里
total: res.count || 0 于是永远是 0，totalPages=1，分页器不渲染。
表现：搜到 33 条只显示 9 条，用户既看不到「共 N 篇」，也无法翻页。
实测（修复前）：搜 LoRA 页面显示 7 张卡但 #pagination 为空。
修法：count 为 null 时补一次计数查询（只 select('id')，不拉正文）。
并抽出 buildArticleQuery / countArticles，让列表与计数共用同一套筛选条件。

2. 搜索词含逗号直接报错
Api.listArticles({search:'a,b'}) 抛
"failed to parse logic tree ((title.ilike.%a,b%,...))"。or() 用逗号做分隔符，
用户输入里的逗号会破坏语法；同类元字符还有 ( ) " % _ * 反斜杠。
修法：新增 sanitizeSearch()，把这些字符替换成空格，再转义 LIKE 通配符。

3. 多词搜索恒为 0 结果
原来拿整串当一个子串匹配，所以「上下文 工程」「微调 LoRA」都返回 0，
而这两个词全站到处都是，用户会以为站点没有相关内容。
修法：新增 buildOrFilter()，按空格切词、每词在标题/摘要/正文三字段里找、
词间取并集（限 6 个词，避免表达式过长）。

验证（对照线上真实数据）：
  无搜索      修复前 33            修复后 33
  LoRA        修复前 0（分页消失）  修复后 7
  上下文      修复前 0             修复后 24
  上下文 工程 修复前 0             修复后 28
  微调 LoRA   修复前 0             修复后 10
  RAG,Agent   修复前 抛解析错误     修复后 26
  (测试)      修复前 抛解析错误     修复后 10
  第 2 页每页 3                    total 19 / 3 条
UI 实测：分页器恢复为「第 1 / 4 页 · 共 33 篇」，上一页/下一页可点。
